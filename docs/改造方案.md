## 1. 整体架构

```
                         ┌──────────────────────────┐
                         │      浏览器 / 终端        │
                         └──────────────┬───────────┘
                                        │  HTTPS
                          ┌─────────────▼─────────────┐
                          │      Nginx (TLS/WAF)      │  :80/:443
                          │  /portal  /api/portal/*   │
                          │  /trader  /hta  /llm      │
                          └──────┬──────────┬─────────┘
                                 │          │
                ┌────────────────▼──┐   ┌───▼────────────────────┐
                │  hermes-portal    │   │  下游服务（直连调试用）  │
                │  FastAPI BFF:9000 │   │  hermes-trader :8000    │
                │  + Vue 静态资源    │   │  HTA            :8766   │
                │  JWT/RBAC/审计    │   │  LiteLLM        :4000   │
                └──┬──────┬──────┬──┘   └────────────────────────┘
                   │      │      │              ▲
        ┌──────────▼┐ ┌───▼───┐ ┌▼──────────┐   │
        │ push 渠道  │ │ 币种  │ │ 提醒/语音  │───┘ （BFF 代理时注入
        │ (飞书等)   │ │ 配置  │ │  配置      │      X-Internal-Token）
        └───────────┘ └───────┘ └───────────┘
```

**核心思路：Portal Shell + BFF**

- **前端 Shell**：Vue 3 SPA，统一布局/导航/权限指令/全局提醒与语音播报。
- **BFF 层**：FastAPI 集中处理 JWT 签发、RBAC 校验、配置存储、审计日志、下游反向代理；对下游注入 `X-Internal-Token`，下游无需各自实现登录。
- **混合集成**：
  - 原生页面（总览/持仓/配置/推送/币种/告警/审计/用户/HTA 研判）直接调用 BFF；
  - 第三方或重交互页面（复盘报告、Studio）走 iframe 嵌入；
  - 其余数据通过 BFF API 聚合，避免前端跨域与多次握手。

## 2. 技术栈选型

| 层 | 选型 | 理由 |
|----|------|------|
| 前端框架 | Vue 3.5 + `<script setup lang="ts">` | 生态成熟、上手快，团队既有 Vue 经验 |
| 构建 | Vite 5 | 冷启动快、HMR 丝滑、生产 Rollup 打包 |
| 状态 | Pinia | Vue 3 官方推荐，TS 友好 |
| 路由 | Vue Router 4 | 全局 `beforeEach` 做登录与权限拦截 |
| HTTP | Axios | 拦截器统一注入 Bearer、401 单飞刷新 |
| 图表 | ECharts 5 + vue-echarts | K 线/曲线/柱状图按需 `use()` 打包 |
| 样式 | TailwindCSS 3 + CSS Variables | 深/浅主题、原子化、零运行时 |
| BFF | FastAPI + Pydantic v2 | 异步高性能，自动 OpenAPI |
| ORM | SQLAlchemy 2.0 async + aiosqlite/asyncpg | 可从 SQLite 平滑切到 PostgreSQL |
| 鉴权 | python-jose JWT + passlib[bcrypt] | 标准化方案，access/refresh 双 token |
| 代理 | httpx AsyncClient | 原生 async，SSE 用 `client.stream` 透传 |
| 部署 | Docker + Nginx | 多阶段构建，镜像小，回滚快 |

## 3. 页面集成方案

| 方式 | 适用场景 | 优点 | 缺点 | 本项目采用 |
|------|----------|------|------|-----------|
| **原生 Vue 重写** | 高频/强交互/需统一权限的页面（持仓、配置、推送、币种、告警、审计） | 体验一致、可共享状态与组件、可深度定制 | 初期工作量大 | 主要模块全部重写 |
| **iframe 嵌入** | 第三方/独立子应用（复盘报告、Studio、LiteLLM Admin） | 改造成本最低、隔离强 | 通信靠 postMessage、SEO/移动体验差 | `Postmortems.vue` 等用 iframe |
| **BFF API 聚合** | 跨服务拼装数据（总览、HTA 研判） | 前端一次请求、BFF 做裁剪/字段脱敏 | BFF 复杂度上升 | 总览/HTA 采用 |
| **微前端（qiankun/wujie）** | 多框架长期共存的大型团队 | 独立部署 | 基建成本高、样式污染 | **暂不采用**，未来可平滑迁移 |

BFF 代理示例（节选）见 [proxy.py](file:///home/ldy/hermes-portal/app/routers/proxy.py)，对 SSE 路径使用 `StreamingResponse` + `httpx.AsyncClient.stream()`，并设置 `X-Accel-Buffering: no` 让 Nginx 透传。

## 4. 统一认证与 RBAC

### 4.1 登录与 Token 流程

```
浏览器 → POST /api/portal/auth/login {username,password}
BFF   → 校验 bcrypt → 签发 access(15m) + refresh(7d)
浏览器 → 后续请求 Authorization: Bearer <access>
401   → 单飞刷新 /auth/refresh → 重放原请求
```

## 5. 业务功能实现

### 5.1 多渠道推送配置

- 支持 **飞书 / 钉钉 / 企业微信 / Telegram / 自定义 Webhook** 五类渠道。
- 每渠道独立「启用开关」、`webhook_url / token / secret` 等字段；敏感字段后端返回 `"******"`，前端提交时若为该占位符则保留原值。
- 「测试推送」按钮实时校验连通性；所有写操作记录审计日志。
- 代码：[push.py](file:///home/ldy/hermes-portal/app/routers/push.py) · [PushSettings.vue](file:///home/ldy/hermes-portal/src/modules/push/PushSettings.vue)

### 5.2 弹窗与语音提醒

- 弹窗位置：右下角 / 左下角 / 右上角 / 屏幕中央（四选一卡片）。
- 语音：
  - **系统默认**：浏览器 `SpeechSynthesis` TTS；
  - **自定义**：上传 mp3/wav/ogg（≤2MB），可试听/删除，文件落盘 `/data/voices`。
- 事件类型：按「交易/风险/智能体/系统」四类分组，支持分类全选；共 9 种事件（开仓/平仓/成单/止损/风险/系统错误/智能体信号/熔断/模式切换）。
- 全局组件 [AlertPopup.vue](file:///home/ldy/hermes-portal/src/shared/components/AlertPopup.vue) + [useVoiceBroadcast.ts](file:///home/ldy/hermes-portal/src/shared/composables/useVoiceBroadcast.ts) + [alerts store](file:///home/ldy/hermes-portal/src/stores/alerts.ts) 协同工作，任何业务代码 `alerts.emit({type,title,content,level})` 即可触发弹窗与语音。
- 代码：[alerts.py](file:///home/ldy/hermes-portal/app/routers/alerts.py) · [AlertSettings.vue](file:///home/ldy/hermes-portal/src/modules/alerts/AlertSettings.vue)

### 5.3 独立币种配置

- 对一个或多个指定币种隔离配置，互不干扰。
- 模式：`signal_only`（仅输出信号）/ `auto_trade`（开启自动交易）。
- 每个币种独立：
  - 推送开关 + 推送渠道多选；
  - 告警阈值（亏损 %、波动率、短时价格异动 %）；
  - 隔离交易参数 `trade_params`（JSON 覆盖全局）；
  - 备注 / 启停开关。
- 支持「测试推送」单币种验证。
- 代码：[coins.py](file:///home/ldy/hermes-portal/app/routers/coins.py) · [CoinConfig.vue](file:///home/ldy/hermes-portal/src/modules/coin/CoinConfig.vue)

### 5.4 校验 / 即时生效 / 审计

- **参数校验**：Pydantic v2 `field_validator`（币种大写+字母数字、模式枚举、阈值范围）+ 前端表单双重校验。
- **即时生效**：保存后 BFF 写库并返回最新记录；前端同步更新 Pinia store（`alertStore.config = data`），下一次事件触发即用新配置。
- **审计日志**：[services/audit.py](file:///home/ldy/hermes-portal/app/services/audit.py) 提供 `write_log()`，在推送/币种/告警/用户/操作员模式等所有写接口处调用，记录 `actor / action / target / before / after / ip / ua`；查询接口见 [audit.py](file:///home/ldy/hermes-portal/app/routers/audit.py)。

### 5.5 高价值衍生功能

### 7.2 `app/core/permissions.py`（JWT + RBAC）

完整文件：[permissions.py](file:///home/ldy/hermes-portal/app/core/permissions.py)。关键片段：

```python
from fastapi import Depends, Header, HTTPException, status
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from app.core.database import get_db
from app.core.security import decode_token
from app.models import User

async def get_current_user(
    authorization: Optional[str] = Header(default=None),
    db: AsyncSession = Depends(get_db),
) -> User:
    """JWT 认证依赖：校验签名/过期/类型/用户状态，失败抛 401。"""
    token = _extract_token(authorization)
    if not token:
        raise HTTPException(401, "未提供认证令牌", headers={"WWW-Authenticate": "Bearer"})
    payload = decode_token(token)
    if not payload or payload.get("type") != "access":
        raise HTTPException(401, "认证令牌无效或已过期")
    user = (await db.execute(select(User).where(User.id == payload["sub"]))).scalar_one_or_none()
    if not user or not user.is_active:
        raise HTTPException(401, "用户不存在或已停用")
    return user

def require_permissions(*required: str):
    """RBAC 依赖工厂：AND 语义，缺任一权限抛 403。"""
    async def _checker(user: User = Depends(get_current_user)) -> User:
        owned = {p.code for role in user.roles for p in role.permissions}
        missing = [p for p in required if p not in owned]
        if missing:
            raise HTTPException(403, f"权限不足，缺少：{', '.join(missing)}")
        return user
    return _checker

def require_roles(*roles: str):
    """角色校验：用户须属于给定角色之一。"""
    async def _checker(user: User = Depends(get_current_user)) -> User:
        if not {r.code for r in user.roles}.intersection(roles):
            raise HTTPException(403, f"角色不足，需要：{', '.join(roles)}")
        return user
    return _checker
```

## 8. 前端核心页面：HTA 研判面板

完整文件：[HtaResearch.vue](file:///home/ldy/hermes-portal/src/modules/hta/HtaResearch.vue)。

**职责**：输入币种 → 经 BFF 调用 HTA 多智能体 `/research` → 渲染综合决策/置信度/关键指标/各分析师观点/风险提示；支持普通请求与 SSE 流式；骨架屏、错误重试、历史记录、研判完成后触发全局提醒。

关键实现要点：

- **接口调用**：默认 `POST /api/portal/hta/research`；流式模式用原生 `fetch` + `ReadableStream` 读取 SSE，手动拼 `Authorization: Bearer`，逐行解析 `data:` 负载。
- **加载状态**：无数据时显示骨架屏（shimmer 动画）；流式时显示已收到的 chunk 数与累积文本。
- **异常处理**：`AbortController` 支持取消；区分 `CanceledError` 与真实错误；错误横幅带「重试」按钮。
- **结果渲染**：综合决策卡（做多/做空/中性，颜色区分）、置信度进度条、六宫格关键指标、分析师列表、风险清单、原始 JSON 折叠。
- **历史记录**：最近 10 条存内存，点击回放。
- **即时告警**：研判完成调用 `alerts.emit({type:'agent_signal',...})`，按用户订阅的事件类型决定是否弹窗/语音。

核心 script 片段：

```ts
async function runResearch() {
  const coin = coinInput.value.trim().toUpperCase();
  if (!coin) return;
  loading.value = true; error.value = ''; result.value = null;
  abortController = new AbortController();
  try {
    if (streamMode.value) {
      await runStream(coin, Date.now());
    } else {
      const { data } = await http.post('/api/portal/hta/research',
        { coin, stream: false }, { signal: abortController.signal });
      result.value = data;
      pushHistory(coin, data);
      alerts.emit({ type: 'agent_signal', title: `${coin} 研判完成`,
        content: `决策：${signalLabel(data.decision)}，置信度 ${data.confidence ?? '—'}%`,
        level: 'success' });
    }
  } catch (e: any) {
    error.value = e.response?.data?.detail || e.message || '研判请求失败';
  } finally {
    loading.value = false;
  }
}
```

## 12. 后续演进路线
